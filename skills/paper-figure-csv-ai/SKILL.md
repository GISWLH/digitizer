# Paper Figure CSV AI

Use an image model to identify a single target series, then measure the original
figure with Digitizer's THU engines. Generated red pixels are a selection hint,
not observed values. Deliver the source, prompt, raw model output, reviewed
registration, original-pixel mask, CSV, grid and comparison together.

## Setup and route

Install the [Digitizer repository](https://github.com/GISWLH/digitizer) in an
isolated Python environment (`python -m pip install -e '.[ai,pdf]'` from its root).
Run `digitizer --help` to check availability. The bundled frozen AI cases can be
replayed with `python scripts/validate_ai.py` without credentials or paid calls.

- Use `digitizer extract` first when colour and shape already separate the data.
- Use `ai-prepare → ai-edit → ai-extract` when semantic selection or filling
  visible marker interiors helps separate curves, points and clutter.
- Use `digitizer grid` for fixed-x line samples or calibrated heatmap cells.
  Grid lines are drawn by code after extraction, never by a generative model.
- Prefer author CSV/Excel over figure digitization when available. Keep numerical
  references out of prompts and extraction; use them only for later evaluation.

## Review the original before any edit

Render the relevant PDF page with `digitizer render-pdf`, then select the panel.
Inspect full-figure context for shared axes. Use `digitizer inspect` to draft a
hash-bound config. Verify plot bounds, at least two ticks on each numeric axis,
linear/log scaling, units, original target colour, marker/line style and series
identity. Unknown coordinates stay blank; never insert 0 or a guessed location.

Inspect every legend, swatch, note, arrow, panel label and inset. Exclude tight
rectangles/polygons rather than entire rows or columns. Preserve visible data
between separated annotations. Opaque legend backgrounds stay excluded even if
an image model later paints a convincing curve through them. Record each mask's
`verified: true`, the config's `reviewed: true` and a concrete `review_note`.
Agent visual review is sufficient; do not ask for repeated user confirmation.

## Prepare a precise target prompt

```bash
digitizer ai-prepare --config figure.json --series measured_NEE \
  --target 'thin solid BLUE measured NEE; not red dashed estimates or the blue uncertainty ribbon' \
  --mode line --out runs/figure-edit
```

For scatter use `--mode markers`; describe the colour, shape, outline and target
identity explicitly. The versioned prompt generated by this command:

1. Locks geometry, axes, ticks, panel boundaries and padding.
2. Removes legend keys/text and other reviewed exclusions before recolouring.
3. Recolours only the visible target stroke, or fills only existing marker interiors.
4. Removes non-target curves, error bars, ribbons, fit lines and pre-existing red
   distractors inside the plot; preserves calibration context outside it.
5. Forbids extrapolation, smoothing, completing clipped markers, filling hidden
   spans, inventing samples or drawing a replacement chart.

Do not use the old instruction “keep all other lines and legend unchanged” when
red distractors or same-colour legend keys would contaminate the red mask.
`--legacy-prompt` exists only for a labelled A/B control. See
[prompt and review guide](references/workflow.md).

## Explicit image-provider request

Credentials must be in environment variables, never in prompts, CLI arguments,
logs or repository files. A paid request requires a user-authorized image-edit
workflow. One call is made; failures do not trigger retries or model fallback.

```bash
# APIYI; set APIYI_API_KEY privately in the environment.
digitizer ai-edit --bundle runs/figure-edit --provider apiyi --model gpt-image-2.5-vip

# Alternative: Nano Banana Pro via the same explicitly selected provider.
digitizer ai-edit --bundle runs/other-edit --provider apiyi --model gemini-3-pro-image-preview

# Direct Google route uses GEMINI_API_KEY.
digitizer ai-edit --bundle runs/google-edit --provider gemini --model gemini-3-pro-image-preview
```

Model IDs are provider-specific. On 2026-10-13, APIYI listed
`gpt-image-2.5-vip`; the historical `gpt-img-2.5-vip` returned HTTP 503. Inspect
`request.json` and report failure honestly. Never describe cached output as a
fresh run or an untested provider as verified.

## Review the returned image and extract

Open original and generated images. Check target identity, missing marks,
geometry changes and remaining distractors. Measure at least four matching
spine/tick landmarks spanning both plot dimensions. Complete `review.draft.json`
with exact image hashes, a review note and
`anchor_pairs: [[original_x, original_y, edited_x, edited_y], ...]`.

Dimensions alone are not calibration. The tool fits only an axis-aligned
transform from reviewed landmarks; inconsistent anchors are rejected. Reject
nonlinear distortion rather than changing calibration to make a score look good.

```bash
digitizer ai-extract --bundle runs/figure-edit \
  --review runs/figure-edit/review.json --columns 49 --out runs/figure-result
```

The default 3-source-pixel neighbourhood gates original colour evidence.
Unsupported generated strokes cannot directly create measurements. Scatter
candidates are detected in the original before AI selection, so a generated dot
cannot turn a clipped piece of fitted line into a new marker. This proximity
check does not prove series identity: inspect crossings and same-colour overlaps.

## Grid extraction and delivery

```bash
digitizer grid --config figure.json --columns 49 --out runs/line-grid
digitizer grid --config heatmap.json --out runs/cell-grid
```

Line grids sample the nearest original column and keep missing columns empty.
Heatmaps preserve cell row/column labels and calibrated original colours. Never
recolour quantitative heatmap values before measuring them; endpoint saturation
must remain an interval. A grid CSV is not automatically a daily/monthly record:
retain axis semantics and choose sampling density explicitly.

Inspect `support-overlay.png`, `overlay.png`, `grid-overlay.png`, `data.csv`,
`grid.csv` and `ai-report.json`. Recreate plots only from extracted CSV.
Report coverage and uncertainty separately from accuracy. Use independent
references for a defined hit-rate/F1 metric; count missing values as misses.
Do not claim universal >90% or that filling necessarily improves accuracy.

For research exports use `digitized_approximation`, original units, DOI, panel,
source hash and extraction uncertainty. Apply the subproject's station baseline
rules before admission; a showcase figure is not a confirmed new flux station.
